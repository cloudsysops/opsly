# ADR-033 One-Page Summary

**Decision:** Integrate Syra with OpenClaw LLM Gateway via direct function calls  
**Status:** ✅ RECOMMENDED | **Date:** 2026-05-08 | **Architect:** Hermes Agent

---

## The Problem in 30 Seconds

```
❌ Syra generates social content with hardcoded templates
   - Low quality (no intelligence)
   - No cost optimization
   - No caching of similar content

✅ OpenClaw (LLM Gateway) already solves this
   - Smart routing (Sonnet vs Haiku vs Cheap)
   - Semantic caching (83.9% hit rate)
   - Budget enforcement
   - Fallback chain

🎯 Solution: Use OpenClaw in Syra
```

---

## The Decision: Three Options Evaluated

```
┌─────────────────────────────────────────────────────────┐
│ OPTION 1: Direct Integration ← SELECTED ✅              │
│ Syra imports and calls OpenClaw functions directly      │
│ ├─ Latency: 0ms overhead                               │
│ ├─ Complexity: 1 service                               │
│ ├─ Operability: Simple                                 │
│ └─ Pattern: Already used in codebase                   │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│ OPTION 2: HTTP Wrapper Service ❌ REJECTED             │
│ Syra → Wrapper → OpenClaw (via HTTP)                    │
│ ├─ Latency: +100ms overhead (8% slower)                │
│ ├─ Complexity: 2 services                              │
│ ├─ Operability: Complex                                │
│ └─ Benefit: None (doesn't solve real problem)          │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│ OPTION 3: Async Message Queue ❌ REJECTED              │
│ Syra → Queue → Worker → OpenClaw                        │
│ ├─ Latency: +1250ms overhead (100% slower)             │
│ ├─ Complexity: 3 services                              │
│ ├─ Operability: Very complex                           │
│ └─ Benefit: None (Syra needs sync response)            │
└─────────────────────────────────────────────────────────┘
```

## Architecture: What It Looks Like

```
Event (from Brissa)
    ↓
Syra.generateContent()
    │ buildSmartPrompt()
    │ inferTone()
    ↓
llmCallWithFallback()  ← Direct function call (no HTTP)
    ├─ Intent detection
    ├─ Semantic cache (83.9% hit!)
    ├─ Complexity analysis
    ├─ Budget check
    ├─ Smart routing:
    │  ├─ Template: Free
    │  ├─ Haiku: $0.001
    │  ├─ Sonnet: $0.02
    │  └─ Cache hit: $0.0001
    └─ Fallback chain
        ├─ Sonnet
        ├─ Haiku
        ├─ Mixtral
        └─ Template
    ↓
Response + Metrics
    │ {
    │   content: "✨ Feature shipped... 🚀",
    │   model_used: "claude-3.5-haiku",
    │   cost_usd: 0.001,
    │   cache_hit: false
    │ }
    ↓
Platform formatting (Twitter, LinkedIn, Discord, Slack)
    ↓
Publish + Store metrics
```

## Questions & Answers

**Q: What if OpenClaw goes down?**  
A: Fallback chain handles it. Syra falls back to templates and continues.

**Q: Will posts be delayed?**  
A: No. Direct calls are instant (1.25s total time).

**Q: Is this safe to deploy?**  
A: Yes. Feature flags allow gradual rollout (10% → 50% → 100%).

**Q: Can we revert if needed?**  
A: Yes. One feature flag flip = instant rollback (5 minutes).

**Q: What about multi-tenant support?**  
A: Each tenant has own budget ($10/month) enforced by gateway.

**Q: Does this scale?**  
A: Yes to 10,000+ posts/month. Beyond that, consider wrapper.
